[Python AI 서버 팀 개발 규칙]

이 문서는 Python AI 서버를 팀원들이 함께 개발하기 위한 최소 공통 규칙이다.
구체적인 패키지명, 라이브러리, 클래스명, 파일명은 아직 확정하지 않는다.


1. 기본 구조

- Python AI 서버는 우선 하나만 운영한다.
- 서버 내부에서 기능별 모듈을 분리한다.
- 기능마다 요청 규격, 전처리, 모델 처리, 응답 규격을 따로 관리한다.
- 기능이 추가될 때마다 Python 서버를 새로 만들지 않는다.
- 모델 크기나 실행 환경 때문에 실제 문제가 생길 때만 서버 분리를 논의한다.


2. 기능별 코드 분리

새 AI 기능은 아래 역할이 구분되도록 작성한다.

- API 요청을 받는 부분
- 요청과 응답의 데이터 형식을 정의하는 부분
- 데이터 전처리와 모델 추론을 담당하는 부분
- 모델을 학습하는 부분
- 학습된 모델을 보관하는 부분
- 기능을 검증하는 테스트 부분

실제 디렉터리명과 파일명은 기능 개발을 시작할 때 팀에서 정한다.


3. 서버 간 호출 규칙

- 프론트엔드는 Python AI 서버를 직접 호출하지 않는다.
- 프론트엔드는 백엔드를 호출하고, 백엔드가 Python AI 서버를 호출한다.
- Python AI 서버는 분석, 예측, 분류, 추천 결과를 반환한다.
- DB 저장, 사용자 인증, 문자·전화 같은 실제 작업 실행은 기존 담당 서버에서 처리한다.
- Python AI 서버의 결과는 백엔드가 한 번 검증한 뒤 사용한다.


4. 학습과 실행 분리

- 모델 학습 코드와 API 실행 코드는 분리한다.
- API 요청이 들어올 때마다 모델을 다시 학습하지 않는다.
- 학습을 완료한 모델을 파일로 저장하고, 서버는 그 모델을 불러와 예측한다.
- 새 데이터가 쌓이면 별도의 재학습 과정을 거쳐 모델을 교체한다.
- 모델이나 데이터가 준비되지 않았으면 임의의 결과를 만들지 않고 준비되지 않은 상태를 반환한다.


5. 새 기능 개발 전에 정할 내용

각 기능 담당자는 개발 전에 아래 내용을 팀에 공유한다.

- 해결하려는 문제
- 모델의 입력값
- 모델이 반환할 결과
- 사용할 데이터의 출처
- 정답 데이터가 무엇인지
- 성능을 어떤 기준으로 평가할지
- 백엔드와 주고받을 데이터 형식

이 내용이 정해지지 않은 상태에서 모델부터 만들지 않는다.


6. API 규칙

- 기능별 API를 구분한다.
- 요청과 응답 형식을 명확하게 정의한다.
- 필수값이 없으면 임의로 추측해서 채우지 않는다.
- 오류를 정상 결과처럼 반환하지 않는다.
- 모델 결과에는 필요한 경우 모델 버전, 신뢰도, 판단 근거를 포함한다.
- API 형식을 변경할 때는 백엔드 담당자와 먼저 합의한다.


7. 공통 코드 규칙

- 한 기능의 내부 코드를 다른 기능이 직접 가져다 쓰지 않는다.
- 여러 기능에서 실제로 동일하게 사용하는 코드만 공통 영역으로 이동한다.
- 공통 패키지를 새로 추가하거나 버전을 변경할 때는 팀에 공유한다.
- 특정 라이브러리를 팀 표준으로 정하려면 먼저 비교 근거를 공유하고 합의한다.


8. Git에 올리지 않을 항목

- 실제 환경설정 파일과 비밀키
- Python 가상환경
- 캐시와 임시파일
- 원본 개인정보 데이터
- 용량이 큰 학습 데이터
- 팀에서 저장하기로 합의하지 않은 모델 파일

필요한 환경변수 이름과 설치 패키지 목록은 예제 파일 또는 실행 문서로 공유한다.


9. 최소 테스트 규칙

각 기능에는 최소한 아래 항목을 확인할 방법이 있어야 한다.

- 정상 요청 처리
- 잘못된 요청 처리
- 모델 파일이 없는 경우
- 모델 추론 실패 처리
- 백엔드와 주고받는 데이터 형식

모델을 직접 학습하는 기능은 학습 데이터와 별도의 검증 데이터로 성능을 확인한다.


10. 기능 추가 순서

1) 문제, 입력, 출력, 데이터, 평가 기준을 정한다.
2) 백엔드와 요청·응답 형식을 합의한다.
3) 기능별 모듈을 만든다.
4) 데이터 전처리와 학습 코드를 만든다.
5) 모델을 학습하고 성능을 확인한다.
6) 저장된 모델을 불러오는 추론 기능을 만든다.
7) API에 연결한다.
8) 백엔드와 통합 테스트한다.
9) 실행 방법과 모델 정보를 짧게 기록한다.


11. 현재 합의할 핵심

- Python 서버 하나에서 시작한다.
- 기능별 코드와 모델은 분리한다.
- 학습과 API 실행을 분리한다.
- 프론트엔드는 백엔드를 통해서만 AI 기능을 사용한다.
- 구체적인 패키지명과 구현 이름은 기능 담당자들이 비교 후 결정한다.
- 공통 구조나 API를 변경할 때는 팀에 먼저 공유한다.
